# ADR-016: Price Sync Center — admin UI design (design only, downstream of ADR-015)

> **Standing (2026-10-09):** In force. Build and live status: [`prd.md` §15](../prd.md). The text below is a dated record; a later addendum in this file overrides earlier text, including the **Status** line.

**Status:** Accepted (design) — 2026-07-26 (same session as ADR-015, continued grilling against two real references: a "Sync Details" modal mockup and the actual legacy `admin.keroxshop.com` Price Sync page)

**Context:** Immediately after ADR-015 locked the backend mechanism, the founder asked to design the "Price Sync Center" UI too, reasoning that once the data model is known, there's no need to wait to *design* it — only to wait to *build* it (ADR-015's build-sequencing is unchanged: this feature is built after ADR-015 ships, not alongside it). Two real references anchored the design: (1) a "Sync Details" modal screenshot showing per-game grouped price/cost diffs, and (2) the actual live legacy KeroxShop admin panel's `/price-sync` page (screenshot, 26 Jul 2026) — used strictly as UI/UX layout inspiration, per this project's own long-standing rule (`legacy-reference-notes.md`) that the legacy system is never a source of product facts, only interface reference.

**Decision:**

1. **Page structure**, `/middleware/price-sync` — five sections: stat cards (Total Games / Active Packages / Pending Reactivation count / Last Sync Status / Last Check), a Last Sync Details panel, the Pending Reactivation table (from ADR-015, now with bulk **Approve All**/**Dismiss All** per SYNC-6), a new **Manually Dismissed Packages** section, and a paginated **Sync History** table whose rows open a **Sync Details** modal (per-game breakdown).
2. **Terminology corrected against the legacy reference, not copied blindly** (its field semantics don't map 1:1 onto this project's domain model):
   - **"New"** in any created/updated/removed summary = a brand-new raw item discovered in the supplier catalog this run (Stage 1's own `created` count) — **not** a newly-promoted `Package`. Promotion stays a separate, manual, Stage 2 action; a Price Sync run never creates a `Package`.
   - **"Price" / "Cost"** columns = `reseller_cost_price` (labeled **"Reseller Price"** — a reseller's cost basis, corrected mid-session: this is *not* what the end customer pays, since a real reseller's own markup, `Reseller.markup_pct`, applies on top of it at checkout) and `cost_price` (labeled **"Cost"** — the Platform's own wholesale cost from the supplier).
   - **"Games Total/Success/Failed"** = derived from the run's overall status × the count of distinct games touched, not real per-game success/failure. Stage 1 is one atomic API call across the whole catalog, so partial per-game failure isn't a state this system can actually produce — a failed run marks every touched game "failed," a successful run marks them all "success."
   - **"Games Synced X/X"** ratio kept as-is (matches the legacy admin's existing mental model), even knowing it will always render as a 100% ratio in this system — propagation checks every promoted package's game on every run, never a subset.
3. **New section beyond the original ADR-015 minimum, adopted from the legacy screen:** **Manually Dismissed Packages** — a browsable list of `deactivated_reason='admin'` packages with a "Restore" action, giving the admin one place to review every package that's off for admin reasons, instead of hunting through `/admin/games` individually.
4. **"Refresh" and "Sync All Prices Now" are distinct actions** — Refresh only refetches this page's current data; only "Sync All Prices Now" dispatches a new `SyncSupplierPricesJob`. Kept deliberately separate so an admin can't mistake a page reload for triggering a real supplier hit.
5. **New field beyond ADR-015's original schema**: `price_sync_runs.triggered_by` (nullable — `'system'` or the triggering admin's identity), so Sync History can show who/what started each run once manual and (eventually) scheduled runs exist side by side.
6. **Currency Rate widget (SYNC-3) confirmed omitted**, per this same session's earlier decision — the legacy reference does show a live `MYR → IDR` rate section, confirming it's a real, previously-solved problem for a multi-currency supplier, but this project has only one supplier (Gamevion, MYR) today. Reasoning preserved here so it isn't lost: build this widget if/when a non-MYR supplier is actually onboarded, not speculatively now.

**Rationale:** Every correction in decision #2 follows this project's own established discipline for the legacy system: reference UIs are adopted for layout/interaction patterns, never for their field semantics or data assumptions, which must always be re-derived from this project's own domain model, not assumed to transfer.

**Consequence to track:** This ADR is **downstream of, and dependent on, ADR-015's data model** (`price_sync_runs`, `price_change_logs`, `deactivated_reason`/`deactivated_at`) — designed before either ADR is built. **Explicitly expected to be revised** if anything changes during ADR-015's actual implementation that this design assumed (a different run-status granularity, a renamed field, a mechanism that doesn't work as designed here) — this is not a frozen contract independent of ADR-015; it inherits ADR-015's own risk of changing on contact with real code, and should be amended rather than treated as locked if that happens. Like ADR-015, this records design intent only — no code exists yet; build happens after ADR-015 ships.

**Addendum, 2026-07-26 (build session) — assumptions confirmed, no revision needed:** ADR-015 shipped this same day (see its own shipped addendum). Every schema assumption this ADR made ahead of that build held exactly as designed — `price_sync_runs.status`/`triggered_by`/`stats`, `price_change_logs`, and `deactivated_reason`/`deactivated_at` all landed with the shapes and names assumed here, including this ADR's own decision #5 addition (`triggered_by`). The "Reseller Price"/"Cost" terminology correction (decision #2) is already reflected in the minimal `/middleware/price-sync` page ADR-015 shipped. Still not built: the full Center UI itself (stat cards, Sync History, Sync Details modal, Manually Dismissed Packages) — this ADR remains design-only.

**Consequence to track:** any *future* `Cache::remember()` call in this codebase must follow this same discipline from the start — cache a plain array, never a model/Collection — or it will silently reproduce this exact bug the moment it's cache-hit in a real environment. Regression tests for all four fixes force `config(['cache.default' => 'database'])` inside the test itself, since the suite's default `array` driver structurally cannot catch this class of bug — a plain "call the endpoint twice" test without that override proves nothing.

**Addendum, 2026-07-27 (build session) — ADR-016 shipped, one schema addition beyond either ADR's original design:** the full Price Sync Center UI (decision #1's five sections) is now built: stat cards (`GET /middleware/price-sync/stats`), Sync History (`GET /middleware/price-sync/runs`, paginated) with a per-game Sync Details modal (`GET /middleware/price-sync/runs/{run}/details`), and Manually Dismissed Packages (`GET`/`PATCH .../dismissed-packages`, new `DismissedPackageController`). `PendingReactivationController`'s own query was extracted into `PendingReactivationFinder` so the stat card's count and the queue itself never drift from each other.

One real gap surfaced on contact with the actual data: neither ADR-015 nor this ADR's original design gave Deactivation Detection any per-run audit trail — `PackagePriceSyncService::deactivate()` only ever incremented an aggregate counter, so a past run's Sync Details modal could show price/cost diffs (from `price_change_logs`) but had no way to know *which* game a deactivation in that run belonged to. Fixed by adding a new `deactivation_logs` table (`price_sync_run_id` nullable-on-delete, `package_id` cascade-on-delete — same shape as `price_change_logs`) and writing one row per actual deactivation. Historical runs from before this table existed simply render an empty deactivation list in the modal, not an error — an accepted, disclosed trade-off, not a bug.

Terminology (decision #2), the Refresh/Sync-All separation (decision #4), and Currency Rate's omission (decision #6) all shipped exactly as designed. Verified live in a real browser (not just `phpunit`): triggered a run, confirmed stat cards and Last Sync Details update, opened the Sync Details modal and confirmed the per-game price/cost diff and deactivation grouping render correctly, and confirmed Restore on a manually-dismissed package reactivates it regardless of live supplier status. Full backend suite: 361 tests, all green (10 new: `DeactivationLog` write-path + `PriceSyncController::index/stats/details` + `DismissedPackageController`).
