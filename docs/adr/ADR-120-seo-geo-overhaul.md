# ADR-120: SEO/GEO overhaul — brand-correct meta, per-brand canonical origin, machine-readable catalog

> **Standing (2026-10-09):** In force. Build and live status: [`prd.md` §15](../prd.md). The text below is a dated record; a later addendum in this file overrides earlier text, including the **Status** line.

**Status:** Accepted, built, **live** — released 2026-10-08 via #369 (#365 PR-1, #366 PR-2, #367 PR-3, #368 hygiene). Grilled with the founder in two rounds (`/mattpocock-skills:grilling`, Q1–Q17), after a live audit of `pekangame.com` + `fixfastapp.com`, the code, and read-only prod data. Revises ADR-029 decision 8, builds ADR-060 §E (canonical, decided but never built), resolves ADR-042's addendum-3 "Consequence to track", extends ADR-042 decision 12. Build: four PRs into `staging`, one release to `main`.

**Context:** A founder question about GEO (being cited by ChatGPT/Perplexity/Gemini) led to a full SEO audit. Verified findings, 2026-10-08:
- **Literal tokens on every game page.** All 38 active games carry the same per-game `seo_title`/`seo_description` — `Instant {game_name} Top Up & Membership Rates | {store_name}` — but `order/[slug]/page.tsx` substitutes tokens only in the Meta Templates fields (ADR-029 decision 8). Google, WhatsApp previews and AI bots got the raw `{game_name}`. The per-game field also outranks the template, so the admin's own BM template was never used. Google had not indexed any game page yet (GSC URL Inspection: "unknown to Google"; sitemap first submitted 2026-10-07).
- **Affiliate domains point at the platform.** `SITE_URL` is one env value, so on `fixfastapp.com` the sitemap (42 URLs), `robots.txt` `Sitemap:` line, `llms.txt` (41 links), Organization `url` and Breadcrumb items all read `https://pekangame.com`. No page anywhere carries `<link rel="canonical">` — ADR-060 §E decided it, nothing built it.
- **Only 12 of ~49 packages are in the HTML** (`PackageGrid.tsx` slices to `COLLAPSED_COUNT`); the rest exist only in the RSC payload, which text-reading AI crawlers don't parse.
- **Product JSON-LD has no `offers`/`aggregateRating`** (Google wants at least one); Organization has no `logo`/`sameAs`.
- **`Store unavailable` (unknown host, incl. `*.vercel.app`) answers HTTP 200.** An invalid game slug answers 200 too, but already carries `noindex` — cosmetic, not in scope.
- Already fine: meta *content* is admin-central on the primary for every brand, only pixel IDs per brand (`SeoController::settings()`, ADR-060 addendum); `robots.txt` allows every AI crawler; SSR. Fixed during the audit without code (founder-approved): Vercel `www.pekangame.com` / `pekangame.space` / `www.pekangame.space` redirects 307 → 308.

**Decision:**

1. **Each domain is its own site (ADR-060 §E as written, Q1).** Canonical, sitemap, `robots.txt` `Sitemap:` line, `llms.txt` and JSON-LD origins come from the resolved brand's own primary domain. Not canonical-to-platform: an affiliate pays for a storefront, and pointing its canonical at `pekangame.com` would take its search presence. Near-duplicate risk is reduced by per-brand names/prices; a per-affiliate "index my storefront" toggle is added only if Search Console shows cannibalisation.
2. **The backend owns the canonical origin (Q13).** The public branding payload gains `canonical_origin`: an affiliate's active `is_primary` `affiliate_domains` row as `https://<hostname>`, the platform brand's `services.storefront.url` (`STOREFRONT_URL`'s first entry). Not the request `Host` — that would make every alias (`www.`) self-canonical. `NEXT_PUBLIC_SITE_URL` stays only as the no-backend/dev fallback. A primary-domain change must bust the branding cache.
3. **Every page carries `<link rel="canonical" href="{canonical_origin}{path}">`** (no query string), plus `metadataBase` and `og:url` (Q14). Non-primary domains keep serving the full storefront with the canonical pointing at the primary.
4. **Tokens render in every SEO text field (revises ADR-029 decision 8, Q2).** One shared resolver substitutes `{game_name}`/`{store_name}` in per-game title/description, default title/description, templates and `llms.txt`; the last hardcoded fallback becomes `Top Up {game_name} - {store_name}`, never a literal "PekanGame". Per-game SEO stays global across brands (ADR-029 decision 1) — which is exactly why `{store_name}` must work there. The per-game admin screen shows the same token hint as the Templates screen.
5. **Per-game SEO is for exceptions (Q3).** After release, the 38 identical per-game title/description values are cleared through the admin UI (not a DB patch), so the primary's BM template governs every brand, including new games. Fallback order is unchanged and already central: per-game → primary template → primary default → hardcoded (Q15 needed no build).
6. **Meta title language is BM** (the primary's template); page UI and `lang="en"` stay as they are. No hreflang (Q8).
7. **Crawler rules stay global and platform-owned (resolves ADR-042 addendum-3 consequence, Q12).** Bot allow/block and `crawler_default_disallow_paths` are one platform set; only the `Sitemap:` line varies per domain. Affiliates can't edit crawler rules.
8. **All packages render in the HTML (Q4).** Packages past the collapsed count are hidden with CSS until "show more", not sliced out.
9. **Product JSON-LD gains `offers` (extends ADR-042 decision 12, Q5)** — an `AggregateOffer` (`lowPrice`/`highPrice`/`offerCount`, `priceCurrency: MYR`, `InStock`) built from the anonymous `selling_price_sen` the guest page already renders: Standard price per brand, affiliate markup included. Never a member or personalised price; no admin-typed price field; governed by the existing Product toggle.
10. **`aggregateRating` (Q6)** from the same brand-scoped review data the page already shows, emitted only when that brand has at least one approved review for that game; no new toggle. **Moderation policy:** reject only spam or abusive text, never a low rating — a filtered-positive average misleads customers and breaks Google's review guidelines.
11. **Organization JSON-LD (Q7):** `url` = canonical origin, plus `logo` (`logo_url`) and `sameAs` (`social_links`) from existing branding.
12. **A generated per-game fact line in the HTML (Q10)** — price range, delivery mode (ADR-109's `delivery_mode`), required IDs, payment method — from existing data, no new field. Concrete facts are what an AI answer quotes.
13. **FAQ becomes admin-central content (Q9):** a table edited in the admin panel with `{store_name}` support, rendered as homepage text plus `FAQPage` JSON-LD, replacing `placeholder-data.ts`'s hardcoded list. Lowest priority of the batch — Google no longer shows FAQ rich results for most sites; the value is AI-readable text and no more hardcoded copy.
14. **`Store unavailable` answers a non-200 with `noindex` (Q16)** — built as **503**, matching what the page itself says (a suspended domain is temporary), via the `proxy.ts` rewrite status.
15. **Build order (Q17):** PR-1 meta + canonical (decisions 2–4, 7, 11, 14) → PR-2 GEO (8–10, 12) → PR-3 FAQ (13) → PR-4 hygiene (`CrawlerRuleSeeder` labels/groups — `ChatGPT-User`/`PerplexityBot` are answer-time fetchers, not training bots; docs `.space` → `.com`; Vercel 308 recorded) → one `staging` → `main` release → admin cleanup (decision 5) and GSC Request Indexing.

**Rationale:** Every fix routes through a seam that already exists rather than adding a parallel one: the central-meta merge in `SeoController::settings()`, `renderTemplate()`, the `is_primary` domain model and `StorefrontBrand`'s per-brand origin (already trusted for CHIP return URLs), the anonymous SSR package fetch. No new admin field is created for any value the system can compute (price, rating, origin) — the same "nothing to drift" rule `sitemap.ts` and `llms.txt` already follow. Rejected: `llms-full.txt` (no adoption evidence, ADR-043 stands); per-affiliate crawler control; canonical-to-platform for affiliates.

**Consequence to track:**
- **Before PR-2, a pricing code-trace (AGENTS.md step 2):** confirm the anonymous `selling_price_sen` equals what a guest is charged at checkout on every basis — Standard, Affiliate brand markup (incl. `max_markup_pct` clamp), and that Member/ResellerWallet prices can never reach the SSR render the JSON-LD reads.
- Primary-domain changes (`AffiliateDomainService`) must bust the brand's branding cache, or a stale canonical survives the TTL.
- Decision 5's cleanup is a founder-approved admin action after release, recorded in `docs/build-log.md` with before/after.
- Open, not in scope (founder deferred): GA4 property, default OG image, Bing Webmaster Tools. GSC Change of Address skipped — no `.space` property and a 5-week-old, unindexed site; the 308s carry it.
- Re-check Search Console coverage after release for canonical/duplicate reports across `pekangame.com` and affiliate domains — decision 1's toggle is the planned response if they cannibalise.
