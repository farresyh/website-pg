# ADR-140: SEO meta strategy and per-game content — one meta rule per page type, a structured primary-only "About this game", and the one status that tracks it

> **Standing (2026-11-11):** In force; revises ADR-120 decisions 5 and 6, ADR-043 decision 22 and ADR-029 decision 1. Build and live status: [`prd.md` §15](../prd.md). The text below is a dated record; a later addendum in this file overrides earlier text, including the **Status** line.

**Status:** Accepted (design only). Grilled with the founder in three rounds (`/mattpocock-skills:grilling`, Q1–Q17) after a live audit of Search Console, the code and the public catalog API, then stress-tested against real code (the findings are decisions 5, 7, 8 and 11). Build: two PRs into `staging` (PR 1 meta strategy, PR 2 game content), one branch each, after the founder has read this file. PRD §16 item 178.

**Context:** The founder asked why almost no game page is indexed. Verified 2026-11-11 (Search Console for `pekangame.com`, `curl` as Googlebot, the public catalog API, Google Trends for Malaysia):

- **Google has never crawled a game page.** 10 pages are indexed (home, `/check-id` and its five children, `/price-list`, `/about-us`, `/refund-policy`); none is under `/order/`. 41 are "Discovered – currently not indexed" with *Last crawled: N/A*: the 37 `/order/*` pages, `terms`, `privacy`, `track-order` and `/joki`. The two "Crawled – currently not indexed" URLs are a font and an icon.
- **Everything mechanical is clean.** `robots.txt` allows all; Crawl Stats (the property's data runs from 6 Oct): 632 requests, 96% 200, no 5xx, host status "No problems", TTFB about 0.2 s on `curl` (five requests); the sitemap (48 URLs, 37 games) was read on 10 Nov, Success; every page has a self canonical and no `noindex`; the home page's raw HTML has 37 unique plain `<a href>` links to the game pages with descriptive anchor text and no `nofollow`, and Google's stored copy of the home page (URL Inspection, View crawled page) contains the same links.
- **What Google does with the site.** Crawl Stats: HTML is 9% of requests, purpose is Refresh 98% and Discovery 2%: Googlebot re-reads what it knows and rarely explores. The Links report shows **0 external links**. Performance (3-month view, data from 6 Oct): 140 clicks and 353 impressions from 9 queries, almost all brand ("pekangame" 45 clicks, "pekan game" 28, "pekgam" 58 impressions and 1 click). Google's own crawl-budget guide says demand depends on size, update frequency, page quality and relevance, that more popular URLs are crawled more often, and that duplicate content wastes crawl time.
- **The game pages have almost no content of their own.** Of 37 games, 26 have an empty `description` and 10 have a short region notice (9 Mobile Legends at ~20 words, PUBG 39). All 37 `seo_title` and `seo_description` are empty by ADR-120 decision 5, so one template writes every title and description. The page body is the price grid plus ADR-120's generated fact line; `description` and `important_notes` show only in the ADR-109 popup.
- **Meta has no rule.** `default_meta_title` / `default_meta_description` are null in the admin, so the home page, `about-us`, `refund-policy` and `track-order` all fall to one hardcoded English sentence ("Fast, secure game top-ups at PekanGame. Delivered in 3 minutes.") as their description. Static page titles are hardcoded in each `page.tsx`. Every indexed page's meta is English; the game template is mixed ("Top Up {game_name} Murah & Instant Delivery | {store_name}").
- **What Malaysians type is mixed too** (Google Trends, Malaysia, 12 months, relative): "top up mlbb" 15, "topup mlbb" 9, "top up mobile legends" 8, "beli diamond ml" 4, "diamond mlbb murah" 2; rising: "diamond ml murah", "top up ml murah"; "codashop" recurs. Volumes are small, so this is direction, not a measurement. The game template is close to how people search; the static pages are what is off.
- **Dead and misleading fields.** `seo_title_local`, `seo_description_local` and `seo_keywords` are read by nothing in `storefront/` (ADR-109 already noted it); `_local` holds one literal template with unreplaced `{game_name}` tokens on 37 of 37 games, `seo_keywords` is empty; they are referenced in five places (admin page and type, `Game`, `UpdateGameSeoRequest`, `CatalogController`) plus the original migration. `GameSeoController::index` sets `seo_status` from "`seo_title` AND `seo_description` filled", and `Admin/SeoController` builds the "SEO Complete" card the same way, so after decision 5 of ADR-120 every game reads "missing".
- **Sitemap hygiene.** Static routes use `lastModified: new Date()` (always "now"); a game's `lastmod` is its `created_at`; `no_index` exists only in the detail payload (`CatalogController::publicGameDetail`), not in the index summary the sitemap reads, so a game the admin marks `noindex` would still be listed.
- **Games arrive three ways** (`GameController`, `SupplierProductController`, `JokiCatalog`) without anyone writing content. All 37 were created in September 2026; none since 29 Sept.
- **Seams already there:** `$brand->is_primary` (one row, DB-enforced; `PlayerCheckController` uses it for ADR-123 decision 10); the per-brand caches (`catalog.index.brand.{id}`, Next's Data Cache partitioned by `X-Storefront-Host` + `__brand`); the save path (`GameSeoController` already calls `forgetIndexCache` and `forgetPackagesCache`); `jsonLdHtml` (escapes `<`); a FAQPage builder inline in `app/page.tsx` (ADR-120 decision 13); the Reseller API catalog (`ResellerApi/CatalogController`) selects explicit `Game` columns, so a new column cannot leak through that endpoint (PR 2 re-checks the other Reseller API reads of `Game`).

**Decision:**

*Part 1 — meta strategy (PR 1)*

1. **One registry for static page meta.** A single file in `storefront/src/lib` gives each static route (`about-us`, `terms`, `privacy`, `refund-policy`, `track-order`, `price-list`, `check-id`) its own title and description, with `{store_name}`, so an affiliate's copy carries its own name. Not an admin table: this text has no business decision in it and almost never changes; the cost is that editing it takes a release. The home page keeps using `default_meta_title` / `default_meta_description` from the admin; the hardcoded English fallbacks are removed (the founder fills the two fields after release).
2. **One vocabulary rule (revises ADR-120 decision 6).** Meta for brand and game pages uses the words Malaysians type: gaming terms stay English ("top up", "diamond", "UC", "instant"), with "murah" and "Malaysia", and the common short forms ("MLBB", "ML") where natural. No page-level meta states a delivery time the data does not give (the "3 minutes" claim goes). The page UI stays English and `lang="en"`.
3. **Game meta description chain (revises ADR-120 decision 5):** per-game `seo_description` (an exception) → the game's `content_summary`, cut at a word boundary to about 155 characters (primary brand, published only, decision 5) → `meta_description_template` → `default_meta_description`. The title chain is unchanged. An affiliate has no summary, so it keeps the template.
4. **Sitemap.** Static routes carry no `lastmod`. A game's `lastmod` is `content_published_at`, else `created_at`; price changes never move it. Games with `no_index` are left out; the index summary gains `no_index` (not a secret, sent to every brand). Organization JSON-LD gains `alternateName` for the primary brand, computed by splitting the CamelCase store name ("PekanGame" → "Pekan Game"; omitted when it does not split): people type "pekan game" and "pekgam", and the entity should resolve. No new field.
5. **Remove the dead fields in two releases (expand/contract).** Release 1 stops every read and write of `seo_title_local`, `seo_description_local` and `seo_keywords` (admin, `Game`, request, controller, type). A later release drops the three columns, so an instance still running the old code during a zero-downtime deploy never writes to a missing column. The founder accepted the loss: the data is one repeated template and an empty column.

*Part 2 — per-game content (PR 2)*

6. **Four columns on `games`, structured, plain text, all optional:** `content_summary` (≤300 characters: one or two sentences, what `llms.txt`, JSON-LD and an AI answer quote), `content_about` (≤2000, paragraphs split by a blank line, no HTML or markdown), `content_faq` (JSON list of `{question ≤150, answer ≤500}`, at most 8), and `content_published_at` (nullable timestamp). Validated in a FormRequest. Status is derived, never stored: **Empty** (no field filled), **Draft** (filled, not published), **Published**. Editing published content takes effect at once. The prefix `content_` keeps it apart from the ADR-109 `description` / `important_notes`, which stay the customer notice in the popup; the Edit Game label "Description (optional)" becomes "Customer notice (popup)".
7. **Primary brand and published only, enforced at one backend seam.** `CatalogController` emits the content keys in the game detail, and `content_summary` in the index summary, only when the resolved brand is `is_primary` **and** `content_published_at` is set. The storefront renders what it receives, so the page, `llms.txt`, JSON-LD and the sitemap `lastmod` cannot leak a draft or reach an affiliate. A non-primary owned brand gets nothing either, which matches "only PekanGame". Same rule as ADR-123 decision 10, same flag.
8. **One status, not two.** The content status replaces the `seo_status` field-completeness reading in `/admin/seo/games` (filter, column, summary) and the "SEO Complete" card on the overview, which become "Published N of M". "Tracked games" is one predicate, defined once on the backend and used by the sitemap and the admin count: active, visible to the primary brand, not `no_index`. Per-game `seo_title`, `seo_description` and OG image stay as exceptions and stop counting as "missing" when empty.
9. **Where it renders.** On `/order/[slug]`, after the reviews section (`GameReviewsSection`) and before the footer, so the buying flow does not move and the reviews stay next to it. Page order: product card, fact line, checkout form, reviews, About + FAQ, footer (founder confirmed 2026-11-11). Server-rendered, visible (no collapse, no popup), under an `<h2>`, with `lang="ms"` on the section, as React text nodes. The FAQ renders visibly and the same items feed `FAQPage` JSON-LD through **one shared builder**, extracted from `app/page.tsx` (the home FAQ uses it too), with a test that the JSON-LD questions equal the rendered ones. Product JSON-LD `description` takes `content_summary`, else the meta description. An empty or draft section is absent: the page stays on sale and indexable.
10. **GEO.** `llms.txt` appends the summary to a game's line (primary, published only). No `llms-full.txt`, no per-page markdown endpoint (ADR-120 already rejected them for lack of adoption evidence). This is the one admin-authored field `llms.txt` has; ADR-043 decision 22's "no admin-authored field" gets an exception for it.
11. **Content is written by a person, grounded in real inputs.** The founder reviews and enters it through the admin; there is no generator in the app and no import command. Claude drafts from catalog data (region, ID format, delivery mode, packages) and official publisher sources, with the sources cited, in one file for review. Siblings in a `family` (MLBB ×10, Free Fire ×6, Valorant ×5) must differ materially (region lock, currency, payment methods, delivery, accepted ID or server), no inheritance logic; a one-off similarity check on the drafts runs before entry and is not kept in the repo. Order: MLBB, Free Fire, PUBG, Genshin, HSR, ZZZ, Valorant, Wuthering Waves first, the rest after. Content language: Malay, casual, English gaming terms kept. An in-app draft generator becomes its own ADR only if new games start arriving often.
12. **Admin.** The fields live on **Admin → SEO → Games → [game]**, which PR 2 rebuilds on the PrimeReact `components/ui` kit (ADR-038; `/admin/orders` is the style benchmark) so it is not half old, half new. Only an admin edits it.

*Measuring*

13. **Baseline 2026-11-11:** 10 indexed, 41 "Discovered", no game page crawled, HTML 9% and Discovery 2% of Crawl Stats, 0 external links, 140 clicks. Re-check at +2, +4 and +8 weeks after PR 2 is live: a game's *Last crawled* is no longer N/A, "Discovered" falls, Discovery % rises, external links above 0. After PR 2 the founder requests indexing for the five top game pages. Backlinks from the brand's social profiles to specific game pages are a founder action with no code; without them the effect is expected to be slow. Results go in `docs/build-log.md`.

**Rationale:** The audit removed every mechanical cause, so what is left is low crawl demand for a new domain with no outside signal and thirty-seven pages that differ only by name. Content cannot make Google crawl a page it has not read, so it is not the whole answer: it is what keeps a crawled page indexed and quotable, and it is the part the codebase controls. Backlinks are the part it does not, which is why decision 13 names them. Every piece reuses a seam that exists (`is_primary`, the per-brand caches and the purge in the save path, `jsonLdHtml`, the FAQ builder, the ADR-038 kit), and each new field has one writer (the admin), one derived status and one enforcement point, so nothing is patched twice. Rejected: a per-affiliate or shared-with-affiliates version (duplicate text across domains, and it would dilute the brand the founder wants to build); `noindex` on affiliate storefronts (their paid product, ADR-120 decision 1); an admin table for static page meta; an in-app generator (new games are rare and a name-only generator invents facts); family inheritance (new logic and edge cases for 29 pages); `llms-full.txt` and markdown endpoints.

**Consequence to track:**
- **Founder admin actions:** after PR 1 is live, fill the primary's `default_meta_title` and `default_meta_description` (record before and after in `docs/build-log.md`); after PR 2, enter the reviewed content in family batches and press Publish.
- **Release order:** PR 1 and PR 2 are independent. PR 2's migration is additive. The three-column drop (decision 5) ships in a release after PR 1 is live. Rolling back content is unpublishing; nothing else depends on it.
- **Tests (the invariant matrix):** brand (primary, affiliate) × status (empty, draft, published) × surface (game detail, index summary, `llms.txt`, JSON-LD, sitemap `lastmod`): only primary × published carries content. No two indexable static pages share a description. FAQ JSON-LD equals the rendered FAQ. A `no_index` game is not in the sitemap. A content save purges the catalog caches (`forgetIndexCache`, `forgetPackagesCache`) and revalidates the storefront.
- **Docs at build:** PRD §15 SEO row, ADR index rows for ADR-029, ADR-043, ADR-120 and this file, and the dated addenda added with this ADR.
- **Affiliate storefronts do not change** beyond the unique static meta and the honest `lastmod`. If an affiliate's own Search Console ever shows its pages outranking `pekangame.com`, ADR-120 decision 1's "index my storefront" toggle is still the planned response.
- **Not verifiable from here:** whether Google will crawl the game pages after this. The checkpoints in decision 13 are how we find out; if the pages are still undiscovered at +8 weeks with content published, the cause is outside the site and the next step is outreach, not more markup.
- **Admin screen and `lang="ms"` are untested until built;** the PR 2 verification needs a live admin screenshot and `getComputedStyle`, not code reading (AGENTS.md step 6).

### 2026-11-11 addendum — PR 1 build notes (decisions 1–5)

PR 1 is built on `feature/seo-meta-strategy`. Where the build had to choose, it chose as follows:

- **Decision 4's "primary brand" needed a source.** `GET /api/catalog/branding` now carries `is_primary` (`(bool) $affiliate->is_primary`, optional on the storefront wire so an older backend parses as false). `alternateName` is `spacedBrandName(storeName)` in `lib/brand-name.ts` ("PekanGame" becomes "Pekan Game"; null when the name has no CamelCase boundary).
- **Decision 1's "remove the hardcoded English fallbacks" is read as "replace them".** An empty `default_meta_title` or `default_meta_description` now falls to the registry's `home` entry, not to nothing, so the home page never ships without a description while the founder has not filled the two fields. The admin value always wins.
- **`price-list` and `check-id` keep their English wording**, moved into the registry unchanged: the first is for resellers, the second already earns impressions for English queries. Their titles and descriptions were unique before.
- **The sitemap rule also governs `llms.txt`.** Decision 4 named only the sitemap; both now read one filter, `indexableGames()`, so a `noindex` game is in neither. The index summary carries `no_index` for every brand (not a secret).
- **A game's `lastmod` is still `created_at` in PR 1**, and a game with no date has none (it used to get "now"). The publish date arrives with `content_published_at` in PR 2. Likewise the `content_summary` step of decision 3's description chain, which needs the column; PR 1 leaves the chain as ADR-120 set it.
- **Decision 5, release 1:** the three fields are out of `Game::$fillable`, `UpdateGameSeoRequest`, `CatalogController`, the admin screen and its type. The columns still exist, so `GET /api/seo/games/{id}` (admin) still returns them inside the model until the drop release. The static-page meta logic and the sitemap rows live in dependency-free modules (`page-meta.ts`, `sitemap-entries.ts`, `indexable-games.ts`) because the storefront's `node --test` cannot resolve the `@/` alias.
