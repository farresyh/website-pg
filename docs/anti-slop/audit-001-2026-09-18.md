Scope: `storefront/` — homepage, `/membership`, footer/nav, FAQ, testimonials. Mode: AFTER (audit existing site). Nothing has been changed yet. Pick which numbers to fix; unlisted numbers are left alone.

## HIGH (Hard Gate — R-02)

**1. Em dash (`—`) appears in live UI copy in at least 3 places — FORBIDDEN, no carve-out applies.**
- Homepage hero subtitle: *"Pick your game, place your order, and pay your way — the fastest top-up experience in Malaysia."* (confirmed on prod + local)
- Search empty state: *`No games match "" — try another search.`* (local; same component likely renders on prod when a search returns nothing)
- `/membership` verification line: *"Verified as farres.work1019@gmail.com — choose a plan below to unlock member pricing on every top-up."*
- Fix: replace each em dash with a period, comma, or colon. Likely one shared copy-writing habit rather than 3 unrelated bugs — worth grepping the storefront source for `—` generally to catch any other instances.

## MEDIUM (Purpose-Gate / Craftsmanship)

**2. Eyebrow badge above the hero H1 duplicates the headline (R-09).**
- Pill badge "🔥 TOP UP MADE EASY" sits directly above "Top up your favorite games in seconds" on the homepage hero. The badge is the exact "Eyebrow Badge Above the Headline" pattern the skill names: it tells the reader nothing the headline doesn't already say. The flame icon is a real inline SVG (not a decorative emoji glyph), so no separate emoji violation — but the badge itself has no functional need.
- Fix: cut the badge, or replace its text with something the headline doesn't already cover (e.g. a real stat or status), per R-09's "functionally needed" bar.

**3. "What Customers Say" carousel reads as thin/repetitive evidence (Craftsmanship C-5 spirit).**
- All 4 visible cards in the first carousel viewport are attributed to the same name, "MUHAMMAD G." Per your ADR-082 memory these are real reviews tied to real orders (not fabricated — so this is not an R-18 fail), but showing one name 4-for-4 undermines "real feedback from verified buyers" as social proof. A visitor scanning it will likely read it as synthetic.
- Fix: cap displayed reviews per customer, or widen the sampled pool so the visible set isn't dominated by one reviewer.

## LOW / notes (no fix required unless you want it)

**4. Local dev only — "New Arrivals" section renders fully blank with no message when the catalog is empty (R-27 gap).** On `localhost:3001` the local backend's `/api/games` 500s (`Route [login] not defined` — an auth/host-resolution issue, not a catalog data issue), so "Popular Picks" and "Quick Top-Up" correctly show honest empty-state text ("Games coming soon.", `No games match ""`), but "New Arrivals" shows nothing at all — no heading-adjacent message. Production is unaffected (catalog loads, section is populated). Only worth fixing if you want every empty state consistent, since this specific case can't currently happen in prod.

**5. No true `<h1>` on the homepage** — the hero heading and every section heading are `<h2>`. Not an antislop rule per se, but worth a mention for SEO/accessibility hygiene while touching this page.

**6. Tooling limitation, not a site bug:** this Chrome automation session could not force the browser window below ~606px width, so true iPhone-width (375–390px) was not directly verified. At 606px the layout held cleanly: 2-column product grid, bottom tab bar (Home/Membership/Track Order/Support), no horizontal overflow, tap targets sized fine. Recommend a quick manual check on an actual phone or DevTools device mode for the narrowest widths (iPhone SE 375px) to fully close out R-03.

- FAQ questions are product-specific ("How long does the top-up process take?", "What should I do if I entered the wrong ID?") — passes R-28.
- Footer is a real 3-column structure (Top Up Games / Company / Support) with real links and a real support email, not the 4-column Product/Company/Resources/Legal template — passes R-05/R-24.

- Broken product artwork falls back to a plain letter-tile placeholder instead of a broken image icon or fake stock photo.
- Order History table on `/membership` uses real, data-driven columns (Date / Game·Package / Order# / Price / Status) with real status badges, not a generic Name/Status/Date/Actions template — passes the app-side table guidance.
