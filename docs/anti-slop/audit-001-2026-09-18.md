# antislop audit 001 — storefront (desktop + mobile)

Date: 2026-09-18
Scope: `storefront/` — homepage, `/membership`, `/price-list`, footer/nav, FAQ, testimonials. Checked live on production (`pekangame.space`) at desktop (1440px) and the narrowest width this Chrome automation session could force (606px). Local dev (`localhost:3001`) also spot-checked. All fixes below live on branch `fix/storefront-copy-and-nav-modal-overlap`, not yet released.

Mode: AFTER (audit existing site), fixed incrementally as the founder confirmed each item.

## Fixed

**1. Em dash (`—`) in customer-facing text — HIGH, R-02.** Turned out systemic once grepped properly: 13 hardcoded SEO `<title>`/`<meta description>` templates, ~26 prose/error-copy strings, 7 table "no value" placeholders, and one image `alt` attribute. All replaced with a plain hyphen, comma, period, or colon depending on context. The homepage hero subtitle's em dash was **not** fixed — it comes from `/admin/herobanner` (admin-editable content), not hardcoded source, so it's the founder's own call to edit or leave.

**3. "What Customers Say" carousel dominated by one repeat customer — MEDIUM, Craftsmanship C-5 spirit.** `ReviewCatalogController::index()` took the latest 12 approved reviews with no per-customer cap, so one real repeat customer's reviews could (and did, on prod) fill most of the visible carousel. Fixed by pulling a larger pool (48) and capping at 2 reviews per customer (keyed by `order.customer_email`) while filling up to 12 slots; shows fewer than 12 rather than padding with more repeats if the distinct-reviewer pool is thin. Test added: `test_homepage_reviews_cap_repeat_customers_so_the_carousel_stays_diverse`.

**7. (found during the session, not in the original pass) RateOrderModal obscured by BottomNav on mobile — HIGH, R-03/C-4.** Both used `z-50`; since `<BottomNav />` renders after `{children}` in `layout.tsx`, it painted over the modal's Submit button on any page where the nav bar is visible (e.g. order-status page after a successful order). Found by the founder on a real phone. Fixed: modal overlay bumped to `z-[60]`. Confirmed only one modal in the codebase had this clash (grepped every `z-50` user).

**8. (found during the session) Quick Top-Up card polish.** Empty-state placeholder and "View All Games" button were too close together (three-way flex auto-margin split); gave the placeholder a fixed bottom margin instead. Button recolored to the primary purple (matches header's "Track Order"). Trust badge copy changed from "Secure FPX & DuitNow Payments" to "Secure Online Payments" — DuitNow QR is still "Activating" in Payment Settings, so naming it specifically overstated what's live.

## Downgraded — not a code bug

**2. Eyebrow badge above the hero H1 ("🔥 TOP UP MADE EASY").** Originally flagged as R-09 (duplicates the headline). Founder confirmed this is admin-editable hero banner content, not hardcoded — same bucket as the hero subtitle. No code fix; founder's own call whether to change the copy via `/admin/herobanner`.

## Still open

**4. Local dev only — "New Arrivals" renders fully blank with no message when the catalog is empty (R-27 gap).** Local-only symptom of the backend's `/api/games` 500 (auth/host-resolution issue, not this bug's fault). Production is unaffected. Not fixed — low priority, can't currently happen in prod.

**5. No true `<h1>` on the homepage** — every heading is `<h2>`. Not an antislop rule, just an SEO/accessibility note. Not fixed.

**6. True iPhone width (375–390px) still unverified by tooling** — this Chrome automation session couldn't force the window below ~606px. At 606px the layout held cleanly (2-col grid, bottom tab bar, no overflow). The one real mobile bug that existed (#7 above) was found by the founder on an actual phone, not by this tooling limitation — recommend a manual pass on a real device before release regardless.

## What already passes (for context, not action items)

- Visual identity is consistent and deliberate: neo-brutalist language (hard 2px borders, offset hard shadows, bold uppercase display type, small consistent radius) — not a generic AI default, reads as a real brand decision (R-01, R-11, R-12, R-20).
- FAQ questions are product-specific — passes R-28.
- Footer is a real 3-column structure with real links and a real support email, not the 4-column template — passes R-05/R-24.
- Every nav/footer link checked resolves to a real route (200), no dead links — passes R-24.
- FAQ accordion, keyboard focus ring (visible 2px outline + offset shadow on `:focus`), and unlaunched game labeled "Coming soon" instead of hidden or faked — passes R-26, R-32, R-38.
- Broken product artwork falls back to a plain letter-tile placeholder instead of a broken image icon or fake stock photo.
- Order History table on `/membership` uses real, data-driven columns with real status badges, not a generic Name/Status/Date/Actions template.
